# UXUTIL/CLAUDE

Utilities for working with Claude: converting *claude.ai* conversations to markdown, and keeping the custom spinner verbs in the Claude Code settings free of duplicates.

All three are executable, so with the *claude/* directory in your *PATH* (like the top-level directory and *git/*) they can be run by name; otherwise run them by path (e.g. *claude/claude2md*).

## Utilities:

### claude2md
*claude2md \[-a\] \[-l\] \[-d dir\] \[-s pattern\] \<file.json\>*
<br>Convert *claude.ai* conversation JSON into readable markdown transcripts.  Accepts either a whole-account *conversations.json* (a JSON array) or a single conversation (a JSON object); with *-d* it writes one *&lt;date&gt;-&lt;title&gt;-&lt;uuid8&gt;.md* per conversation, otherwise it writes to stdout.
Notable options: *-a* include thinking and tool_use/tool_result blocks (default is message text only), *-l* list conversations without writing, and *-s* restrict to titles matching a case-insensitive regex.  Requires *jq*.

Saving a long conversation from the browser does not work — *claude.ai* virtualizes the message list, so *Save Page As* and *Print* only capture the turns currently mounted in the DOM.  The full transcript arrives in a single JSON request, so there are two ways to get at it:

* **Whole account:** *Settings &rarr; Privacy &rarr; Export data*.  The emailed download link **expires 24 hours after delivery**; there is no published SLA on generation time, and deleted conversations are not included.  Unzip and run *claude2md* over *conversations.json*.
* **One conversation:** paste [*misc/claude-fetch.js*](../misc/claude-fetch.js) into the browser console on the open chat.  A same-origin *fetch* sends the session cookie automatically, so nothing is extracted or stored and no public */share/* link is created.  It downloads JSON for *claude2md*.

Note that neither route carries the *bytes* of uploaded attachments or of files generated in-session — only references.  *claude2md* lists their filenames under each message so the gap is at least visible.  A conversation fetched with *tree=True* contains abandoned edit/regenerate branches; *claude2md* walks *current_leaf_message_uuid* back to the root to emit only the live thread, falling back to chronological order for exports (which drop the parent links).
Very large exports are read into memory by *jq* in one pass; a multi-hundred-MB *conversations.json* may need more RAM than a small machine has.

### extract-spinner-verbs.py
*extract-spinner-verbs.py \[--binary path\] \[--lines\] \[-o file | --update | --check \[ref\]\]*
<br>Print the spinner verbs built into the installed Claude Code executable (the words such as *Thinking* shown while it works), as one comma-separated line.  The list is a minified JavaScript array inside the native binary (or the npm *cli.js* bundle); it is located through the code that reads the *spinnerVerbs* setting rather than by a minified variable name, so it survives most Claude Code updates.  When the list can no longer be found, or fewer than 20 verbs are extracted, it stops with an error saying the script needs updating.
The executable is *--binary path* if given, otherwise *claude* on your *PATH* (symlinks resolved), then the newest *~/.local/share/claude/versions/\**, then the common npm global install locations.
Notable options: *--lines* print one verb per line (stdout only; files are always written as one line), *-o file* write the list to *file*, *--update* write it to */tmp/claude/spinner.txt* (the built-in list *verify-spinner-verbs.py* reads), and *--check \[ref\]* compare against *ref* (default */tmp/claude/spinner.txt*) and list the verbs added and removed.  An existing output file is first backed up to *file.YYMMDD-HHMMSS*.
<br>Exit status is 0 on success (or no change with *--check*), 1 if *--check* found a change, and 2 for an error.

### verify-spinner-verbs.py
*verify-spinner-verbs.py \[file ...\]*
<br>Report duplicated custom spinner verbs; no file is ever modified.  It checks the *spinnerVerbs.verbs* array of each settings file given, by default *./.claude/settings.json*, *./.claude/settings.local.json* and *~/.claude/settings.json*; a file that does not exist is skipped.  A verb is reported when it:
* is already built into Claude Code (in the default *append* mode it would be listed twice)
* is repeated within one file
* appears in more than one of the files

Repeats are matched regardless of case.  A verb that differs from a built-in only by case is shown as a warning and does not fail the check.  When duplicates are found, a table at the end shows each one, the files it is in, and whether Claude Code has it built in.
The built-in list is read from */tmp/claude/spinner.txt*; when that file is missing it is regenerated by running *extract-spinner-verbs.py --update* from the same directory as this script, so keep the two together.  Set *SPINNER_BUILTIN* to read a different list (which is then never regenerated).
To check the verbs this repository installs (see [*setup/*](../setup/README.md)) before installing them:
```
$ claude/verify-spinner-verbs.py setup/claude/settings/setting_spinner.json
```
Exit status is 0 if no duplicates were found, 1 if any were, and 2 for a usage, read or JSON error.
